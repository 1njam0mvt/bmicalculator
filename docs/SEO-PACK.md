## 4. How it follows the guide
- **SEO:** semantic HTML, one H1, unique title and description per language, canonical and hreflang (with x-default), sitemap, mobile-first layout, Core Web Vitals-friendly single file.
- **AEO:** a "quick answer" block that opens with the formula and healthy range; FAQ in natural question phrasing with the answer in the first sentence; FAQPage schema that matches the visible FAQ.
- **GEO:** fact-dense answers with WHO and CDC numbers, worked examples (178 cm, 72.5 kg gives 22.9) and a visible "Reviewed" date. Add original data later (surveys, case studies) to raise citation chances.
- **LLMO:** consistent entity name across pages, `llms.txt`, schema types WebApplication, MedicalWebPage, FAQPage, BreadcrumbList, crawlers allowed in robots.txt.
- **E-E-A-T:** medical disclaimer, named sources, review date. Still to add: a named author or reviewer with credentials, an About page, a contact page and a privacy policy page.

## 5. Honest limits and next steps
1. `meta keywords` is ignored by Google; the tag is included because you asked for tags, and the same phrases are worked into the visible text.
2. The other 200 calculators open through `#` addresses, which search engines do not index as separate pages. To rank for "mortgage calculator" and similar, each needs a real URL such as `/mortgage-calculator/` with its own title, description and schema. That is the biggest next SEO step.
3. Only the BMI page is translated into 8 languages. Long sections (risks, limits, formulas) are still English.
4. No tool can guarantee rankings. After launch, submit `sitemap.xml` in Google Search Console and Bing Webmaster Tools, test with the Rich Results Test, and track impressions per language.
5. Have a clinician or health editor review the medical text before publishing.
